# Безопасность

## Права доступа

- Аутентификация — JWT в заголовке `Authorization: Bearer`. Токен выпускает `api`.
- Каждый пользователь имеет набор доступных клиентов; `api` проверяет право **до** вызова
  нижестоящих сервисов (fail closed, ответ `403 forbidden`).
- Внутренние сервисы не публикуются наружу: в compose доступны только через сеть Docker.
- Секреты — только в `.env` (не коммитится); в коде — через `pydantic-settings`, без значений по умолчанию
  для секретов.

## Защита данных

- Исходные данные кейса (`data/raw/`) не коммитятся (`.gitignore`).
- Персональные данные (ФИО контактных лиц и т. п.) не отправляются в LLM: перед вызовом модель
  получает только очищенный профиль. Перечень чувствительных полей — `services/agent/config/safety.yaml`.
- В журналы не пишутся тела запросов с ПДн и полные тексты документов — только идентификаторы.

## Prompt injection

Источники (новости, PDF) — недоверенный ввод.

- Тексты источников подаются модели как **данные** в размеченном блоке; инструкции из них игнорируются.
- Планировщик можно вызывать только с инструментами из белого списка (`config/tools.yaml`) — недоступных
  инструментов, произвольных URL и сетевого доступа у него нет.
- Ответ синтеза проходит критика: утверждение без провенанса не попадает в инсайт.
- Тест на инъекцию — в `services/agent/tests/`.

## Журналирование

- `request_id` генерируется в `api` и передаётся во все сервисы; логи содержат его.
- `RunTrace` — аудит прогонов агента (модели, промпты, шаги).
- Ошибки клиенту возвращаются как `ErrorResponse` без внутренних стектрейсов; детали — только в логах.
