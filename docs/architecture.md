# Архитектура

## Компоненты

| Компонент | Ответственность | Владелец |
|---|---|---|
| `frontend` | SPA: вход, главный экран, лента, инсайт, сравнение | участник 5 |
| `api` | шлюз: аутентификация, права доступа, корреляция запросов (`request_id`), агрегация | участник 6 |
| `profile` | загрузка CSV, признаки клиента, граф связей, полнота данных | участник 1 |
| `ingestion` | парсеры новостей, разбор PDF, нормализация, дедупликация | участник 2 |
| `ranking` | поиск кандидатов, скоринг, объяснение релевантности | участник 4 |
| `agent` | план → инструменты → синтез → критик → трасса | участник 3 |
| `db`, `cache` | PostgreSQL, Redis | инфраструктура |

Диаграмма: [architecture.svg](architecture.svg).

## Поток данных

1. **Загрузка клиентов** — CSV из `data/` → `profile` → признаки, связи, оценка полноты.
2. **Ингестия** — источники → `ingestion` → нормализованные `news_item` → дедупликация → группировка в `event`.
3. **Запрос ленты** — `api` → `ranking` (кандидаты по профилю, скор, объяснение) → `ranked_events`.
4. **Инсайт** — `api` → `agent`: планировщик выбирает инструменты (`profile`, `ranking`, `ingestion`),
   синтез формирует `claims` с `provenance`, критик проверяет → `business_insight` + `run_trace`.
5. **Уточняющий вопрос** — `api` → `agent` (follow-up) с опорой на сохранённые доказательства трассы.

## Принципы

- **Контракты прежде кода.** Всё, что пересекает границу сервиса, описано в `contracts/` и версионировано.
- **Объяснимость.** У каждого факта — провенанс; у каждого скора — причина; у каждого инсайта — трасса.
- **Деградация.** Если LLM или источник недоступны, API возвращает типизированную ошибку (`upstream_error`),
  фронтенд это отображает; результаты ранжирования без LLM остаются доступны.
- **Тесты без сети.** Все тесты работают на заглушке LLM и примерах из `contracts/examples/`.
