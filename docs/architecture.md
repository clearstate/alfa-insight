## Поток запроса «открыть разбор события»

1. **План.** Агент определяет шаги по теме события и признакам компании: профиль → кластер публикаций → сопоставление отраслей с контрагентами (если в событии названы отрасли) → связанные компании (если есть группа) → позиции банка → линзы → сверка чисел с прогнозами банка.
2. **Инструменты** (`TOOLS_ALLOWED`, только чтение): `get_company_profile`, `get_cluster`, `match_supply_chain`, `get_related_companies`, `get_bank_positions`, `get_indicators`, `cross_check_numbers`, `search_bank_corpus`. Вызов вне списка невозможен (assert). Каждый вызов — в трассировку.
3. **Единый контекст.** `Ctx` + `EvidenceBook`: все шаги пишут и читают одни и те же доказательства; итоговые тексты ссылаются на них по идентификаторам.
4. **Анализ.** Линзы (`lenses.py`) возвращают `Finding` (направление, значимость, уверенность, горизонт, гипотеза/нет, сценарии, действия). Знак эффекта, который нельзя установить по данным (ВЭД: импорт/экспорт), подаётся как сценарии и гипотеза.
5. **Синтез.** Правила либо LLM (переписывание под ограничениями).
6. **Самопроверка** (10 проверок): доказательства существуют; каждый вывод обоснован; числа есть в источниках; у позиций банка есть страница; позиция банка приписана только при источнике; есть связь с признаками компании; слух не подан как факт; версии прогнозов; свежесть источника; отсутствие инъекции.
7. **Адаптация** (до 2 итераций): откат фразы к шаблону, восстановление ссылок, расширение поиска по материалам банка со снижением уверенности до «низкой» (проверка помечается `warn`).

## Модель происхождения (сквозная шкала)

`fact` (факт из новости) · `unconfirmed` (слух) · `bank_view` (позиция/прогноз банка) · `bank_data` (данные из материалов банка) · `company_data` (поле CSV) · `rule` (расчёт по правилам) · `ai` (вывод AI, метод `rules`|`llm`). В интерфейсе — цветные бейджи и легенда «Как читать».

## Ранжирование

Вклад = вес × значение компонента: темы (0,34) · отрасль (0,32) · цепочка поставок (0,08) · регион (0,06) · страны ВЭД — только вместе с торговыми темами (0,05) · роль (0,16) · группа (0,04) · бонус материала банка (0,08). Затем множители: надёжность источника, свежесть (период полураспада 18 дней для новостей, 60 — для банка), слух ×0,7, устаревшее ×0,15. Итог — насыщающая шкала 0–100. Исключаются дубли, материалы с признаками инъекции. Лента: события одного кластера схлопываются, материалов банка не более 4, итоговый порядок = 0,8·релевантность + 0,2·значимость вывода.

## Данные для обмена между компонентами

Инсайт — JSON схемы `insight/1.0` (`services/insight/__init__.py`, пример — `GET /api/insights/{id}`): `what_happened`, `why_it_matters`, `consequences{risks,opportunities,notes,scenarios}`, `bank_view{items,indicators}`, `actions`, `offer`, `data_gaps`, `evidence[]`, `checks`, `trace`, `disclaimer`. Источники, позиция банка, признаки компании и выводы модели разделены полями `origin`/`evidence`.
