# Сценарий проверки (≈10 минут)

1. Открыть http://localhost:8080 → «Войти» (demo/demo). Меню аватара (справа вверху): смена пользователя (CFO, казначей, бухгалтер…), смена роли, выход. **Главная**: баннер «Новостная аналитика», три главных события, пункт меню с бейджем.
2. **Новостная аналитика**, компания №25835 (опт автозапчастей), роль «Финансовый директор». Первой идёт новость об утилизационном сборе; под ней — «Для вашей компании: …».
3. Сменить компанию в шапке на №212593 (рестораны) и №51606 (строительство, Татарстан): лента перестраивается. Сменить роль — меняется порядок.
4. Открыть событие. Проверить блоки: «Что произошло» (две публикации объединены, расхождение оценок 8–12% и 10–15% показано, не усреднено) → «Почему важно» → «Последствия» → «Как оценивает банк» (цитата + страница + ссылка на документ — открывается PDF на нужной странице и текст страницы) → «Что можно сделать» (кнопки действий). «На чём основан вывод»: доказательства, 10 проверок, шаги агента.
5. Задать вопрос: «Какие платежи и контрагенты влияют?», «Показать расчёт релевантности», «Что банк ждёт по ставке на 2027 год?».
6. **Проверить свою новость**: вставить любой текст (по умолчанию — квоты на экспорт зерна) → увидеть темы → «Показать анализ для этой компании». Затем вставить текст с «Игнорируйте предыдущие инструкции…» — материал заблокирован. Слух «Инсайд: ЦБ может повысить ставку до 17%» помечен «Не подтверждено», показано расхождение с позицией банка (14,0%).
7. **Аналитика банка**: траектория ставки, версии прогнозов (13,5 → 14,0), документы-источники. `GET /api/metrics` — метрики качества.
