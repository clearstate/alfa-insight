# Масштабирование и сопровождение

## Добавить отрасль

1. Расширить справочник отраслей/ОКВЭД в `profile` (маппинг кодов → отрасль).
2. Добавить словари синонимов и типовых событий для отрасли в `ranking`.
3. Дополнить разметку в `data/eval/` примерами новой отрасли.
4. Прогнать `make eval` и сравнить с базовой линией.

## Добавить источник

1. Написать парсер в `services/ingestion/app/parsers/` с общим интерфейсом.
2. Добавить схему входа в `contracts/schemas/news_item.py` (если отличаются поля) и в `SourceType`.
3. Настроить `NEWS_SOURCES` / `RAW_DATA_URL` и расписание ингестии.
4. Убедиться, что дедупликация не склеивает разные события (порог `dedup.similarity_threshold`).

## Добавить модель

1. Завести переменную в `.env.example` и роль в `services/agent/config/models.yaml`.
2. Промпты не трогать: они версионируются отдельно; при смене поведения — новая версия файла.
3. Прогнать `make eval` и сравнить метрики; обновить `docs/quality-metrics.md`.
4. Обновить `THIRD_PARTY_NOTICES.md` (лицензия и условия использования модели).

## Горизонтальное масштабирование

- `api`, `profile`, `ranking`, `ingestion` — stateless, масштабируются репликами за балансировщиком.
- `agent` — вызовы LLM ограничены лимитом конкурентности; тяжёлые прогоны (пакетный предрасчёт) —
  очередь, а не синхронный запрос.
- Кеш ранжирования и поиска — Redis/индекс; ключ включает `company_id` и версию профиля.

## Сопровождение

- Контракты меняются только через `contracts/` + `CHANGELOG.md`; CI проверяет совместимость.
- Промпты — код: изменения через PR, с прогоном eval.
- Мониторинг: доля прогонов с `critic_passed=false`, латентность, стоимость токенов на инсайт.
