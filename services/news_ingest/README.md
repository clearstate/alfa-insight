# news_ingest — конвейер новостей и аналитики банка (участник 2)

Превращает внешние новости и 9 аналитических документов Альфа-Банка в единый формат `news_item` (контракт `contracts/news_item.py`),
пригодный для поиска/ранжирования (участник 4) и анализа (участник 3). Стыкуется с `company_profile` (участник 1) по **словарю тем v1**
(36 тем) и **префиксам ОКВЭД2**. Главное для расчёта рисков: из таблиц банка извлекаются **числовые прогнозы** (`macro_indicators`,
`forecasts_latest.json`) с автоматическим разрешением расхождений между документами (действует самый поздний).

## Проверка на реальных данных кейса (CSV, 85 525 строк)
- Участник 1: профили 4000 случайных компаний собираются без ошибок; id с коллизией (`U_428697`) → `CompanyQuarantined`, несуществующий → `CompanyNotFound`. Крупный бизнес (выручка > 15 млрд ₽) — **115 компаний** (70 — оптовая/розничная торговля, 20 — строительство).
- Географические значения в данных: страны в ВЕРХНЕМ регистре и списком через запятую (`КИТАЙ`, `ЮЖНАЯ КОРЕЯ`; 128 разных), регионы — 82 официальных названия. Первая версия моих словарей их не совпадала (`Китай`, `Сибирь`) — исправлено: `config/geo_countries.yaml`/`geo_regions.yaml` **генерируются из данных** (`scripts/build_news_geo.py`), тест проверяет, что каждое значение из CSV есть в словаре.
- Сквозной тест `test_integration_real_dataset`: у каждой из 115 компаний есть кандидаты в хранилище (по темам, ОКВЭД и региону), регионы/страны профилей присутствуют в словарях, новость про автомобили находит автокомпании.
- **Различающая способность** (9 документов × 115 компаний): простое пересечение тем почти тотально (100–113 компаний из 115) — **для ранжирования нужны веса**: `Σ topic_score(новость) × weight(профиль)` даёт реальный разброс (например, «Макростатистика 1П26»: квартили 2,06 / 2,70 / 3,62, максимум 5,29). ОКВЭД-совпадения редкие и содержательные (0–15 компаний). Совпадение по стране в макро-документах — упоминание, не торговая связь (обзор золота «задевает» 35 компаний только упоминанием Китая) — учитывать только вместе с темами `foreign_trade`/`fx_rates`/`sanctions`.

## Быстрый старт
```bash
python scripts/run_news_tests.py                               # тесты без pytest
python -m services.news_ingest.cli --db sqlite:///data/news.db ingest-bank   # первая вертикаль: 9 документов
python -m services.news_ingest.cli --db sqlite:///data/news.db export --out data/export   # выгрузка для участников 3/4/6
python -m services.news_ingest.cli --db sqlite:///data/news.db metrics
python -m services.news_ingest.cli import-file note.txt --published-at 2026-09-11          # новая новость файлом
python -m services.news_ingest.cli ingest-url https://...      # (нужна сеть; robots.txt и SSRF-защита)
uvicorn services.news_ingest.main:create_app --factory --port 8002   # API (нужны fastapi/pydantic)
docker compose -f docker-compose.news_ingest.yml up --build    # стенд с PostgreSQL (не запускался)
```
Режим «новая новость» (критерий 5): `POST /api/news/ingest {"url": "..."}` или `{"text": "...", "title": "..."}` — материал проходит
весь конвейер синхронно (секунды), появляется в `GET /api/news` и в `GET /api/news/changes`. Cron: `cli ingest-feed <source_id>`.

## Конвейер
```
источник ─► fetch (SSRF/robots/retry/rate) ─► raw_documents (SHA-256, идемпотентно)
        ─► extract (HTML | RSS | PDF: сайдкар → текстовый слой → OCR) ─► normalize ─► validate
        ─► content_hash ─► dedup/версии/кластер ─► enrich (правила → LLM только если правила не справились)
        ─► save (news_items, chunks, item_topics/industries/regions, macro_indicators) ─► ingest_events (поллинг для участника 4)
```
**Различаем:** `unchanged` (тот же URL и текст — ничего), `update` (тот же URL, текст изменён → `version`+1, старая в `news_versions`),
`duplicate` (другой URL, тот же/почти тот же текст: SHA-256 или MinHash ≥ 0.80 → `dup_of`, запись сохраняется, из выдачи исключается),
`same_event` (независимая публикация: тот же кластер, URL сохраняются; противоречащие цифры не сливаются, а попадают в `event_clusters.conflicts`
и `status_reasons: cluster_conflict`), `new`.

## Материалы банка (PDF)
Все 9 PDF **растровые, без текстового слоя**. Источник текста — сайдкар `data/bank_analytics/<имя>.extract.json` (транскрипция страниц,
привязана к SHA-256 PDF; при несовпадении хэша не используется). Для новых PDF: текстовый слой (pdfplumber) → OCR (tesseract rus+eng; в Docker
ставится `tesseract-ocr-rus`) → при недоступности запись в `pipeline_errors` (`ocr_unavailable`), конвейер не падает.
Страницы-дисклеймеры (`boilerplate`), обложки и разделители не индексируются. Позиции банка (`bank_views`: forecast/assessment/recommendation) и
`key_facts` с `claim_type = bank_view | fact` извлекаются правилами по маркерам («мы ожидаем», «на наш взгляд», «рекомендуем» и др.).
Устаревший отчёт (сталь, апрель 2021) получает `stale_document` и надёжность 0.2.

## Правила и словари (всё в `config/`, без кода)
`topic_rules.yaml` (36 тем v1), `entities.yaml` (органы, лица, геотеги вне РФ), `geo_countries.yaml` + `geo_regions.yaml` (страны и регионы **как в данных кейса**, генерируются), `industry_overrides.yaml` (обход ложных срабатываний основ слов
в словаре участника 1: «порт»→«портфель», «связи»→«в связи с», «бумаг»→«ценные бумаги»), `sources.yaml` (источники, надёжность, лимиты).

## Безопасность
Тексты — недоверенные данные: в LLM идут только как `<document>…</document>` с инструкцией игнорировать команды внутри; подозрение на инъекцию
(`prompt_injection_suspected`) помечается; ответ модели парсится строго (JSON), темы проверяются по словарю, факты — **заземляются**
(только дословные цитаты из текста). Загрузка по URL: только http/https, запрет приватных/loopback/link-local адресов (SSRF), лимит размера,
тайм-аут, ≤3 редиректа с повторной проверкой, robots.txt, белый список доменов (`NEWS_ALLOWED_DOMAINS`), без учётных данных в URL.
XML — без раскрытия сущностей (XXE/entity bomb). Секреты — только ENV. Каждое обращение к `POST /api/news/ingest` пишется в audit-журнал участника 1;
права: `NEWS_INGEST_USERS`/`NEWS_INGEST_OPEN`. Ограничение: DNS резолвится дважды (окно DNS-rebinding) — в проде egress-прокси.

## Бюджет LLM (500 ₽/сутки на всю команду)
По умолчанию модуль работает **без LLM**. Если задан `LLM_BASE_URL`: вызов только если правила не нашли темы или <2 фактов; кеш по хэшу
(модель+версия промпта+вход); дневной лимит `LLM_DAILY_TOKEN_BUDGET` (по умолч. 150 000 токенов на модуль); вход ≤ 6000 символов; учёт расхода в `llm_usage`.
Модель простых задач — Gemma 4 26B A4B (идентификатор задаётся `LLM_MODEL_SIMPLE`; точное имя у провайдера не проверено).

## Метрики качества и мониторинг (критерий 8)
`cli metrics` считает из БД: доля `needs_review`, доля дублей, `failure_rate`, ошибки по кодам, лаг публикации (retrieved−published), элементы без тем,
кластеры с противоречиями, токены/кеш LLM. Рекомендуемый процесс: (1) недельная ручная разметка 30 случайных элементов экспертом
(точность тем, точность `bank_view`, корректность дат) — целевые пороги: темы ≥ 0.8, дата ≥ 0.95, bank_view ≥ 0.85; (2) алерт при
`failure_rate` > 10% или лаге > 6 ч или токенах > 80% лимита; (3) обратная связь пользователей из UI (участник 5) пишется как `claim feedback` по `item_id`;
(4) регрессионный набор фикстур `tests/news_ingest` расширяется каждым найденным дефектом.

## Масштабирование (критерий 7)
Новый источник = запись в `sources.yaml` + (при необходимости) адаптер с интерфейсом «получить байты → `Extracted`»; новая отрасль = строки в
`industry_terms.yaml` участника 1; новая тема = правило в `topic_rules.yaml` + тема в словаре v1 (меняет обе стороны). Дедупликация сейчас O(N) по окну 14 дней
(достаточно для тысяч материалов); при росте — LSH по бэндам MinHash. Поиск candidate-ов — через индексируемые таблицы `item_topics/item_industries/item_regions`;
полнотекстовый поиск (`tsvector`) добавляет участник 4. Сопровождение: все правила в YAML, поведение закреплено тестами.

## Известные ограничения
- **Точность `bank_views` не измерена на размеченной выборке.** Ручная проверка 30 случайных предложений (один проверяющий): ~85% — позиция банка; ошибки — пересказ ожиданий регулятора/рынка («регулятор ожидает…») и описания реакции инвесторов. Темы и отрасли вообще не оценивались по разметке. Перед демо нужна экспертная выборка (см. «Метрики качества»).
- **Автономный API требует `NEWS_STANDALONE_AUTH=demo`** (заглушка X-User-ID) либо монтирования в общее приложение с `app.state.profile_service` участника 6 — иначе `current_user` участника 1 не работает. Заглушка проверена только юнит-тестом, сам HTTP-слой не запускался.
- Без лемматизации (основы слов): возможны ложные срабатывания/пропуски; список обходов — `industry_overrides.yaml`; замечания к словарю участника 1 — `docs/handoff_other_participants.md`.
- Числовые утверждения (`numeric_claims`) — только ставка ЦБ, годовая инфляция, курс USD/RUB; остальное — через `macro_indicators` из таблиц банка.
- Сайдкары — транскрипция по изображениям: возможны единичные ошибки в таблицах; для критичных цифр сверять по `page` + `source_file`.
- Графики не оцифровываются (кроме подписанных значений); Qwen3-VL-путь предусмотрен интерфейсом, не включён.
- Кластеризация событий эвристическая (тот же день, общая тема, общие цифры/сущности): возможна ложная склейка — поэтому противоречия помечаются, а не сливаются.
